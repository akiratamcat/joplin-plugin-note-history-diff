# 検証用プロトタイプ（v0.1.0）

[仕様書](spec.md) 7 章の検証計画を確かめるための、読み取り専用のプラグインです。ノートや履歴は書き換えません。

## ビルド

```sh
npm install
npm run dist
```

`publish/io.github.akiratamcat.note-history-diff.jpl` ができます。

> `package.json` に `"private": true` を入れているので、`npm publish` は失敗します。npm に公開すると公式プラグイン一覧に載ってしまうため、v1 まではこのままにします（仕様書 8 章）。

## インストール

1. Joplin デスクトップ版で「ツール」→「オプション」→「プラグイン」を開く
2. 歯車アイコン →「ファイルからインストール」で上の `.jpl` を選ぶ
3. Joplin を再起動する

## 使い方

1. 履歴が 2 件以上あるノートを開く
2. メニュー「ツール」→「Note History Diff: run verification」、またはノートのツールバーのボタンを押す
3. エディタの横のパネルに結果が出る
4. 「Copy summary」で結果の要約をクリップボードにコピーできる。要約には件数・文字数・時間だけが入り、ノートの本文やタイトルは入らない
5. パネルを閉じるには、パネル右上の「Close」ボタンを押すか、メニュー「ツール」→「Note History Diff: close panel」を選ぶ（v0.1.1 から）

## パネルで確かめること

| パネルの節                         | 確かめること                                                                                                                                   | 仕様書の項目   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| 1. Revision settings               | 履歴の設定（有効・無効、保存日数、作成間隔）が値で表示されるか、エラーになるか                                                                 | 2 章、検証計画 |
| 2. Fetching revisions              | 全件の読み込みにかかった時間。`item_id` での絞り込みと `notes/<id>/revisions` が使えるか（Verdict 列が `filter works` なら使える）             | R1             |
| 3. Rebuilt revisions               | 全版の組み立てが `ok` か。各版の文字数と差分が、Joplin 本体の履歴画面で同じ版を開いたときの内容と合っているか（ここは目で確かめる）            | R2、R3         |
| 4. Latest revision vs current note | 最新の版と今のノートが同じか。ノートを編集して 10 分以上たってから保存し、もう一度実行すると、版が変更前と変更後のどちらの内容を持つかが分かる | F1             |
| 5. Diffs                           | 行単位の差分がパネルに表示されるか。パネルの幅（上部に表示）を変えたときの見え方                                                               | 検証計画       |

結果は、仕様書 7 章の検証計画と R1〜R3 に反映します。
