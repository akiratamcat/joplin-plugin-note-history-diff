# 検証用プロトタイプ（v0.1.0）

[仕様書](spec.md) 7 章の検証計画を確かめるための、読み取り専用のプラグインです。ノートや履歴は書き換えません。

## ビルド

```sh
npm install
npm run dist
```

`publish/io.github.akiratamcat.note-history-diff.jpl` ができます。

> `package.json` に `"private": true` を入れているので、`npm publish` は失敗します。npm に公開すると公式プラグイン一覧に載ってしまうため、v1 まではこのままにします（仕様書 8 章）。

## インストール

1. Joplin デスクトップ版で「ツール」→「オプション」→「プラグイン」を開く
2. 歯車アイコン →「ファイルからインストール」で上の `.jpl` を選ぶ
3. Joplin を再起動する

## 使い方

1. 履歴が 2 件以上あるノートを開く
2. メニュー「ツール」→「[dev] Note History Diff: run verification」を選ぶ（v0.2.0 からツールバーのボタンは製品用の機能に変わった）
3. エディタの横のパネルに結果が出る
4. 「Copy summary」で結果の要約をクリップボードにコピーできる。要約には件数・文字数・時間だけが入り、ノートの本文やタイトルは入らない
5. パネルを閉じるには、パネル右上の「Close」ボタンを押すか、メニュー「ツール」→「[dev] Note History Diff: close verification panel」を選ぶ（v0.1.1 から）

## 大きな本文と、幅による表示の切り替え（v0.1.3 から）

履歴の版ができるのを待たずに試せるよう、2 つのノートを直接比べるコマンドを用意しています。

### テスト用ノート

`test/fixtures/` に、変更前と変更後の Markdown を用意しています。同じ名前のファイルが 2 組あるので、どちらか 1 組だけを取り込みます。

| フォルダ              | 大きさ                     | 用途                   |
| --------------------- | -------------------------- | ---------------------- |
| `test/fixtures/`      | 約 2,600 行・約 6 万文字   | ふだん使う大きさの目安 |
| `test/fixtures/huge/` | 約 17,000 行・約 39 万文字 | 負荷の確認             |

変更後のファイルには、次の変更が入っています：段落の一部の書き換え、箇条書きの追加と削除、表の整形し直しだけの変更、行末の空白だけの変更、コードの変更、長い行の変更、段落の追加、セクションごとの削除。

作り直すときは `node scripts/make-test-notes.mjs`（大きさは `--sections 1000` などで変えられる）を使います。

### 手順

1. Joplin で「ファイル」→「インポート」→「MD - Markdown (File)」を選び、`NHD-test-before.md` と `NHD-test-after.md` を取り込む。ノートのタイトルが `NHD-test-before` と `NHD-test-after` になっていることを確かめる
2. メニュー「ツール」→「[dev] Note History Diff: compare test notes」を選ぶ
3. パネルに次の 3 つが出る
    - テスト用ノートの行数と文字数
    - 100 版の模擬履歴を組み立てた時間（R3）。版が 100 件あるノートがなくても、組み立ての速さを確かめられる
    - 変更前から変更後への差分
4. パネルの幅を 600 px より広くしたり狭くしたりして、差分の表示が横並びと 1 列とで切り替わるかを確かめる。今の表示方式はパネル上部に `layout: …` として出る
5. 「Copy summary」で要約をコピーし、結果を `evidence/` に置く

試し終わったら、2 つのテスト用ノートは削除して構いません。

結果は、仕様書 7 章の検証計画と R1〜R3 に反映します。

## エディタの場所に表示する検証（v0.3.0、`editor-view` ブランチ）

履歴と差分を、横のパネルではなく、エディタが表示されている場所に出す方式（エディタビュー）を確かめます。横のパネルは v0.3.0 でなくなりました。

### 手順

1. v0.3.0/v0.3.1 の `.jpl` を入れ直し、Joplin を再起動する
2. 履歴があるノートを開き、ノートのツールバーの履歴ボタン（または「ツール」→「ノート履歴の差分を表示」）を押す
    - 期待：エディタの場所が、差分の画面に切り替わる
3. 差分の画面の「閉じる」を押す
    - 期待：元のエディタ（Markdown またはリッチテキスト）に戻る
4. もう一度履歴ボタンを押してから、別のノートを開く
    - 期待：別のノートは、ふつうのエディタで開く。元のノートに戻っても差分の画面にはならない
5. 履歴ボタンを押して差分の画面を出したまま、Joplin を再起動する
    - 期待：再起動後は、ふつうのエディタで開く
6. 各手順のあとで「ツール」→「[dev] Note History Diff: editor view status」を選ぶ。状態と直近の動きがダイアログに出て、クリップボードにもコピーされる。うまくいかなかった手順があれば、その内容を `evidence/` に置く

### v0.3.0 の結果と v0.3.1 での変更

v0.3.0 では、履歴ボタンを押しても何も変わらなかった。Joplin は、エディタビューを有効にするかの確認を、ノートの切り替え時などにしか呼び直さず、同じノートのままでは呼び直さない。また `showEditorPlugin` は、有効になっているエディタビューしか表示できない。

### v0.3.1 の結果と v0.3.2 での変更

v0.3.1 では、表示・「閉じる」・切り替えボタン・ほかのエディタ系プラグインとの共存は期待どおりだった。問題は次の 2 つ。

- 表示したまま、履歴がまだない別のノートを開くと、元のエディタに戻らず「版は 1 件だけ…」と表示された
- 表示したまま再起動すると、いったんふつうのエディタが出たあと、履歴の画面に切り替わった

原因は、Joplin が「エディタビューを開いている」状態を覚えていて、ノートの切り替えや再起動のあとにも自動で開くこと。v0.3.1 はこれを「切り替えボタンが押された」と取り違えて、履歴を表示していた。

v0.3.2 では、起動して最初の表示と、ノートを切り替えて 2 秒以内の表示は「Joplin が自動で開いた」とみなし、元のエディタに戻す。

### v0.3.2 の結果と v0.3.3 での変更

v0.3.2 では、ノートを切り替えたときと再起動したときの動きは期待どおりになった。残った問題は次の 2 つ。

- 再起動したとき、エディタ部分が一瞬白くちらつく。Joplin が自動でエディタビューを開き、それをすぐ元に戻しているため。プラグインからは Joplin が開くこと自体を止められないので、**避けられない制約として扱う**

### v0.3.3 の結果と v0.3.4 での変更

v0.3.3 では、起動して 5 秒以上たってからの切り替えは期待どおりになった。起動して 5 秒以内に切り替えボタンを押すと、自動で開いたものと取り違えて元のエディタへ戻そうとし、戻れずに「読み込み中」のまま止まった。

切り替えボタンを最初は無効にしておく案（「ノート履歴の差分を表示」を押すまで無効）も検討したが、このボタンは Joplin 本体のもので、プラグインから有効・無効を切り替える API はない。ビューを「無効」にしておくと、同じノートのままでは有効に戻せない（v0.3.0 で確認済み）。

そこで v0.3.4 では、時間で推測するのをやめ、Joplin が「前回終了時にビューを開いていたか」を覚えている設定（`plugins.shownEditorViewIds`）を、プラグインの起動時に読んで判断する。

- 前回、開いたまま終了した → 起動後の最初の表示は自動で開いたもの。元のエディタへ戻す。
- 開いていなかった → 起動直後でも、最初の表示は切り替えボタンによるもの。履歴を出す。
- 設定が読めなかったときだけ、v0.3.3 の「5 秒以内」の判断を使う。

また、元のエディタへ戻せなかったときは、「読み込み中」のまま止めずに、そのノートの履歴を表示する。

あわせて、履歴が長いときに縦スクロールできなかった不具合を直した（エディタの場所ではビューの高さが固定されるため、ビューの中でスクロールするようにした）。比較する版を選ぶ機能は、次の段階（F2）で作る。

### v0.3.4 の結果と v0.3.5 での変更

v0.3.4 では、起動直後の切り替え、再起動、ノートの切り替え、縦スクロールは期待どおりになった。

残った問題：履歴ボタンで表示 →「閉じる」→ 切り替えボタンの順に操作すると、「ノートの履歴を読み込んでいます…」のまま止まる。

記録を見ると、最後の切り替えボタンで表示されたとき、Joplin から更新の通知（`onUpdate`）が届いていない。プラグインは表示されたことに気づけず、「閉じる」のときに描いた「読み込み中」がそのまま見えていた。Joplin は、同じノートのまま表示と非表示を繰り返すと、更新を通知しないことがあるらしい。

### v0.3.7 の別ウィンドウでの問題と v0.3.8 での変更

v0.3.7 で、ノート一覧でノート名をダブルクリックして別ウィンドウでノートを開いていると、メインウィンドウの切り替えボタンや履歴ボタンで「ノートの履歴を読み込んでいます…」のまま止まることがわかった（2026-11-26、利用者の報告）。

原因：Joplin は、ノートのエディタがあるウィンドウごとにエディタビューを作り、そのたびに `onSetup` を呼ぶ（API の説明どおり）。v0.3.7 までのプラグインはビューを 1 つしか覚えておらず、別ウィンドウのビューで上書きしていた。そのため、メインウィンドウのビューには何も描かれなかった。

- ノートの切り替えは、ビューごとに呼ばれる `onActivationCheck`（どのビューへの呼び出しかが渡される）で知る。これまで使っていた `onNoteSelectionChange` は、どのウィンドウの切り替えかがわからないので使わない。

- 状態の記録は、行の先頭にビューの番号（`[view 1]` など）を付け、ビューごとの状態も出す。

## MVP 3. F2（比較する版を選ぶ）— v0.4.0

v0.4.0 から MVP の続き。比較元と比較先を、版の一覧から選べるようにした。

- 履歴の画面の上に「比較元」「比較先」のドロップダウンを置いた。一覧は「現在のノート」と版を新しい順に並べ、各行に日時と本文の文字数を出す。
- 最初は、これまでどおり F1 の組み合わせ（最新の版と現在のノート、または 1 つ前の版と最新の版）を選んだ状態で開く。
- 選び直すと、組み立て済みの全文から差分だけを計算し直す（履歴は読み直さない）。選び直した後は、「最新の版と現在のノートを比べています」などの説明は出さない。
- 「更新」を押しても、選んだ版はそのまま（その版がまだあれば）。
- 読み込めない版（暗号化されたままなど）は一覧に「読み込めません」と出し、選べないようにする。その版より新しい版も組み立てられないので、同じく選べない。
- 比較元と比較先に同じ版を選ぶと、差分の代わりに「同じ版を選んでいます」と出す。
- 比較元に新しい版、比較先に古い版を選ぶこともできる（差分の向きが逆になる）。

## 次の段階 F9・F7・F6 — v0.7.0

v1 までに作る機能（F9・F7・F6）を、まとめて作ってまとめて確かめる（2026-11-26 に相談して決定）。

- **F9 空白の違いを無視**：「行末の空白と改行コードの違いを無視」のチェックボックスを置いた。最初は有効。比べる前に両方の本文とタイトルから、行末の空白・タブを取り除き、改行コード（CRLF、CR）を LF にそろえる。行頭や行の途中の空白は、これまでどおり差分に出る。チェックの状態はプラグインの内部の値に保存する（設定画面には出ない）。切り替えると、その場で差分を計算し直す。
- **F7 変更箇所へ移動**：「↑ 前の変更」「↓ 次の変更」ボタンを置いた。変更のかたまりの先頭へスクロールし（上に数行の余白を残す）、そのかたまりを一瞬枠で囲む。横並びでも 1 列でも、表示中のほうで動く。変更がない（タイトルだけの変更など）ときはボタンを出さない。
- **F6 前後の版ペア**：版の選択欄の横に「◀ 前の版ペア」「次の版ペア ▶」ボタンを置いた。隣り合う 2 つの版を選んでいるときは、1 つ古い組・1 つ新しい組に移る（例：最新の版→現在のノート から「前の版ペア」で、1 つ前の版→最新の版）。隣り合っていない 2 つを選んでいるときの「前の版ペア」は、新しい側の版で終わる組になる。それ以上古い（新しい）組がないとき、または読めない版を含むときは、ボタンを押せない。
- 3 つは扱う場所が分かれている（差分の計算、webview の中のスクロール、版の選択）。ただし、作業のコミットは機能ごとに分けられなかった（同じファイルに 3 つの変更が入ったため）。

### v0.7.0 の結果と v0.7.1 での変更

F9・F6 と組み合わせの 2 項目は期待どおり。F7 は「↓ 次の変更」を押すと、版の選択欄やボタンまで一緒にスクロールして見えなくなり、続けて押せなかった（「↑ 前の変更」、1 列表示、組み合わせの 1 項目は試せず）。

原因：画面全体が 1 つの領域としてスクロールしていた。

v0.7.1 での変更：画面を上下に分け、上の部分（ツールバー、版の選択、版ペア・変更箇所のボタン、空白のチェック、表示方式）は固定し、下の差分の部分だけがスクロールするようにした。変更箇所への移動も、下の部分の中でスクロールする。

### v0.7.1 の結果と v0.7.2 での変更

上のボタン類の固定、版ペアとの組み合わせは期待どおり。残った問題：「↓ 次の変更」で下へ進み、差分の下端が画面に入ると、まだ下に変更のかたまりが残っているのに、それ以上進まない（横並び・1 列・狭い幅とも）。

原因：今どこにいるかを、スクロールの位置だけで判断していた。下端ではそれ以上スクロールできず、次のかたまりを画面の上に持ってこられないので、毎回同じかたまりを「次」と判断していた。

v0.7.2 での変更：直前に移動したかたまりを覚えておき、それが画面に見えている間は、その次（「↑ 前の変更」ならその前）のかたまりへ進む。下端・上端ではスクロールは動かないが、枠の点滅が次のかたまりへ移る。自分でスクロールして直前のかたまりが画面から外れたら、これまでどおりスクロールの位置から判断する。

### v0.7.2 で確かめること

| 項目                                                 | 期待                                                                                                   | 結果     |     |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | -------- | --- |
| 変更が何か所かある長い差分で「↓ 次の変更」を繰り返す | 下端に近づいてスクロールしなくなっても、枠が残りのかたまりへ順に移る。最後のかたまりの後は何も起きない | 期待通り |     |
| 続けて「↑ 前の変更」を繰り返す                       | 枠が前のかたまりへ順に戻り、上へスクロールしていく。最初のかたまりの後は何も起きない                   | 期待通り |     |
| 1 列表示、600 px より狭い幅で同じ操作                | 同じように進む・戻る                                                                                   | 期待通り |     |
| 途中で自分でスクロールしてから「↓ 次の変更」         | 今見えている位置の次のかたまりへ移る                                                                   | 期待通り |     |

「↑ 前の変更」を試すのにちょうど良いノートがないときは、`test/fixtures/` の NHD-test（before / after）のように、離れた所に何か所も変更がある 2 つの版を持つノートが向いている。
